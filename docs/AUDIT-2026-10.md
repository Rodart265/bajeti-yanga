# Audit follow-ups (October 2026)

The client-side fixes are in `index.html`. Two things **cannot** be fixed from this repo: the AI worker and the Firestore rules.
Both need to be done in the Firebase / Cloudflare consoles.

## 1. AI worker authentication (do this BEFORE or WITH merging)

The client used to send a hard-coded `X-Bajeti-Secret` header. Anyone could read it from the page source and use your
Gemini quota. The client now sends `Authorization: Bearer <Firebase ID token>` instead and no longer contains the secret.

**Deploy order matters** (the worker currently rejects requests without the old header):

1. Update the Cloudflare worker (`nyumba-ai`) to accept EITHER a valid ID token OR the old secret, and deploy it.
2. Merge/deploy this client change. Old cached PWAs keep working via the secret during the transition.
3. After a few days, remove the legacy-secret branch from the worker and **rotate the secret** (treat the old one as public).

Minimal worker check (no extra libraries, uses the public Firebase web API key):

```js
const FIREBASE_API_KEY = 'AIzaSyA5TdvAFE0cFkme7O--LtJNKIikM-KXFdM'; // the public web key already in index.html
const cache = new Map();                    // token -> {uid, exp}

async function authorize(request, env) {
  const auth = request.headers.get('Authorization') || '';
  if (auth.startsWith('Bearer ')) {
    const token = auth.slice(7);
    const hit = cache.get(token);
    if (hit && hit.exp > Date.now()) return hit.uid;
    const r = await fetch(
      'https://identitytoolkit.googleapis.com/v1/accounts:lookup?key=' + FIREBASE_API_KEY,
      { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ idToken: token }) }
    );
    if (r.ok) {
      const uid = (await r.json()).users?.[0]?.localId;
      if (uid) { cache.set(token, { uid, exp: Date.now() + 5 * 60 * 1000 }); return uid; }
    }
  }
  // TRANSITION ONLY - delete this branch, then rotate the secret
  if (request.headers.get('X-Bajeti-Secret') === env.BAJETI_SECRET) return 'legacy';
  return null;
}
// in fetch(): const uid = await authorize(request, env); if (!uid) return new Response('Unauthorized', { status: 401 });
```

Also add a per-uid rate limit in the worker (Workers KV / Durable Object / Cloudflare rate-limiting rule); the client-side
daily counters are advisory only.

## 2. Firestore security rules

The rules are not in this repo, so they could not be reviewed. Please check the live rules enforce the following, and
commit them as `firestore.rules` so they are versioned:

| Concern | What the rules should enforce |
|---|---|
| Premium / trial | Clients must not be able to write `config.isPremium`, `config.premiumExpiry`, `config.trialStarted` (or root-level equivalents). Only an admin/Cloud Function should. |
| Join code expiry | `joinCodeExpiry` is only checked in client code. Enforce it where the join request is created (or move the code into a separate invite document that members-only config does not live next to). |
| Household read | Currently any signed-in user holding the code can read the whole household document (config, member names, budgets). Expose only the fields needed for joining to non-members. |
| AI conversations | `households/{id}/_conversations` is readable/writable by every member. Scope to the owning `uid` if chats should be private. |
| Chip groups | Join is now a transaction, but rules should still require the status to be `gathering` for a `memberUids` addition, and limit what a member can change on their own `members.<uid>` entry. |
| User docs | Users may write only their own `users/{uid}` document. |
| Field validation | Reject non-numeric or negative `amount`, and oversized strings, on `purchases` writes. |

## 3. Still open (not changed in this pass)

- Config edits that replace an **array** (items, bills, goals, users) are still last-write-wins within that array.
  Only changes to *different* config sections are now merged safely. Fixing this properly means moving items/bills/goals into
  their own documents or sub-collections.
- Item/bill/goal edits still use array indexes captured at render time (only "mark bill paid" re-finds by identity).
- Back button: the `popstate` wrapper re-pushes state so the PWA cannot be exited with the back button.
- The Firebase compat SDK (9.22) is old; plan a move to the modular SDK and `persistentLocalCache`.
- Phone-only accounts cannot re-verify in-app for PIN reset (they are told to sign out and back in).
